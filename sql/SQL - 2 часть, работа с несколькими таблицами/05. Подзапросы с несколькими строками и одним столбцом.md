## Подзапросы с несколькими строками и одним столбцом
Такие просто так нельзя использовать с операторами сравнения, как это можно было со скалярами делать

Но с такими типами подзапросов можно использовать три типа операторов

#### Оператор ALL
Сравнивает отдельное значение с каждым значением в наборе, полученным подзапросом

Проверка того, что для всех жилых помещений выполняется условие, что оно дешевле 200

```sql
SELECT 200 > ALL(SELECT price FROM Rooms)
```
#### Оператор IN
Проверяет, входит ли конкретное значение в набор значений.
В качетве набора может использовать результат подзапроса данного типа

Получить информацию о владельцах жилья стоимостью больше 150 условных единиц

```sql
SELECT * FROM Users
WHERE id IN (
	-- выведет уникальные значения id комнат цена которых больше или равна 150
	SELECT DISTINCT owner_id FROM Rooms WHERE price >= 150
)
```

#### Оператор Any
True если хотя бы одно сравнение отдельного значения со значением в наборе вернет true

Можно прошлый разпрос переписать с использованием этого оператора

```sql
SELECT * FROM Users WHERE id = ANY (
    SELECT DISTINCT owner_id FROM Rooms WHERE price >= 150
)
```
#### Многостолбцовые подзапросы
Попарное сравнение значений основного запроса со значениями подзапроса

```sql
SELECT * FROM Reservations
    WHERE (room_id, price) IN (SELECT id, price FROM Rooms);
```

И еще примерчик

```sql
SELECT * FROM Rooms
	WHERE (has_tv, has_internet, has_kitchen, has_air_con)
	IN (
		SELECT has_tv, has_internet, has_kitchen, has_air_con
		FROM Rooms
		WHERE Rooms.id = 11
	)
```

####  Коррелированные подзапросы (зависимые подзапросы)
До этого все подзапросы были независимыми

Эти запросы ссылаются на один или несколько столбцов основного запроса и их нельзя выполнить отдельно от основного запроса

Пример подзапроса 

```sql
SELECT member_name, 
		(SELECT MAX(unit_price)
			FROM Payments WHERE FamilyMembers.member_id = Payments.family_member) as good_price 
			FROM FamilyMembers
```

Здесь FamilyMembers.member_id ссылается на внешнюю таблицу, поэтому запрос коррелированный и вызывается он на каждый айдишник члена семьи

Такие зарпосы надо стараться избегать так как они плохо влияют на производительность из-за множества вызовов
