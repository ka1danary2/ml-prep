```python
class Solution:
    def findPeakElement(self, nums: List[int]) -> int:
        left = 0
        right = len(nums) - 1

        while left < right:
            mid = left + (right - left) // 2

            if nums[mid] < nums[mid + 1]:
                left = mid + 1
            else:
                right = mid
        
        return left
```


Разбор задачи

Главное, что надо понять - что в массиве всегда существует пик из-за условия о том, что по краям множества -inf -> в любом массиве будет пик

От этой идеи и надо отталкиваться

Рассмотрим на примере любого массива, например, [1,2,1,3,5,6,4]
Выберем любой элемент, например, 3

Если элемент index + 1 (5) больше текущего (3), это значит что направо мы поднимаемся в гору и где-то справа точно должен быть пик. В таком случае нам надо идти вправо и можно с помощью бин поиска обрезать половину

Если элемент index + 1 (5) меньше текущего (3), то пиком может быть либо сам элемент (mid) либо элемент слева от него, поэтому можно обреза массив пополам слева

В конце left == right (следует из условия цикла, поэтому можно вернуть и left и right, разницы никакой

Так как условие ГАРАНТИРУЕТ что пик ЕСТЬ, то можно уверенно возвращать left который и будет пиком (или right)

mid точно не может быть пиком потому что в условии сравнения mid нам не подходит
### Про бинарный поиск

**Вопреки заблуждениям, бинарный поиск работет не только в отсортированном массиве, а в любом массиве, где можно за O(1) откинуть половину массива и гарантировать, что результат лежит в другой половину**
